1. INTRODUCTION                                          *gitvim-introduction*

gitvim.nvim assembles Neovim's Git capabilities into one docked, discoverable
surface modelled on VS Code's Source Control view, plus GitLens-style blame and
a Git Graph-style commit graph.

It is an orchestration layer. gitvim owns the sidebar, the graph, the timeline,
the commit UI and the remote operations; it delegates the in-buffer layer
(signs, hunks, blame) to gitsigns.nvim through a single bridge module, so the
coupling stays thin and auditable.

==============================================================================
2. REQUIREMENTS                                          *gitvim-requirements*

    Neovim 0.11 or newer
    git 2.30 or newer
    gitsigns.nvim                                   (required)
    snacks.nvim                                     (optional, sidebar window)
    mini.icons                                      (optional, filetype icons)

Both optional dependencies have fallbacks. Run |:checkhealth| gitvim to see
what was detected.

3. SETUP                                                        *gitvim-setup*

With lazy.nvim: >lua

    {
      "mihovilrak/gitvim.nvim",
      dependencies = { "lewis6991/gitsigns.nvim" },
      cmd = "GitVim",
      keys = {
        { "<leader>gg", "<cmd>GitVim toggle<cr>", desc = "GitVim sidebar" },
      },
      opts = {},
    }
<
Calling `setup()` is optional if you are happy with the defaults; the |:GitVim|
command initialises the plugin on first use.

                                                            *gitvim.setup()*
require("gitvim").setup({opts})
    Merge {opts} over the defaults and initialise. Safe to call once; repeat
    calls are ignored.

                                                             *gitvim.open()*
require("gitvim").open({tab})
    Open the sidebar, optionally focusing {tab} ("files", "search", "git"
    or "buffers").

                                                            *gitvim.close()*
require("gitvim").close()

                                                           *gitvim.toggle()*
require("gitvim").toggle()

4. COMMANDS                                                  *gitvim-commands*

                                                                    *:GitVim*
:GitVim open [{tab}]    Open the sidebar. {tab} is "files", "search",
                        "git" or "buffers"; defaults to
                        `sidebar.default_tab`.
:GitVim close           Close the sidebar.
:GitVim toggle          Toggle the sidebar.
:GitVim blame           Toggle current-line blame.
:GitVim blame-commit    Select the current line's commit in GRAPH.
:GitVim stage           Stage the current file.
:GitVim unstage         Unstage the current file.
:GitVim discard         Discard the current file's working-tree changes
                        (an untracked file is deleted).
:GitVim stage-all       Stage every change, untracked files included.
:GitVim unstage-all     Unstage everything.
:GitVim discard-all     Discard every working-tree change and delete
                        untracked files. Staged changes are kept.
:GitVim commit [--amend] [--signoff]
                        Open the commit message editor, see
                        |gitvim-commit|.
:GitVim fetch           Fetch from the remotes.
:GitVim pull            Pull the current branch.
:GitVim push            Push the current branch. A branch without an
                        upstream is published with `--set-upstream`.
:GitVim checkout        Pick another local branch and switch to it.
:GitVim refresh         Re-read git status for the current repository.
:GitVim status          Echo a one-line summary of the repository.
:GitVim health          Run |:checkhealth| gitvim.

Subcommands and the commit flags complete with <Tab>. Every discard asks
for confirmation first unless `scm.confirm_discard` is false. Remote
operations report their progress with |vim.notify()|.

5. CONFIGURATION                                               *gitvim-config*

`lua/gitvim/config.lua` is the authoritative reference; every key below is
deep-merged over the defaults.

sidebar~
    position        "left"|"right"      default "left"
    width           number              default 40
    stack           boolean             default false
                    Share the side column with an existing split (such as
                    your file explorer) instead of opening beside it.
    tabs            string[]            default { "files", "search", "git",
                                        "buffers" }
    default_tab     string              default "git"
    close_on_open   boolean             default false

files~
    root            "repo"|"cwd"  what the tree is rooted at, default "repo"
    show_hidden     boolean   show dotfiles, default true
    show_ignored    boolean   show .gitignore'd files, default false
    git_status      boolean   tint names by their git status
    follow_buffer   boolean   reveal the active buffer's file

search~
    case_sensitive  boolean   initial state of the [Aa] toggle
    whole_word      boolean   initial state of the [ab] toggle
    regex           boolean   initial state of the [.*] toggle
    include         string    initial "files to include" glob
    exclude         string    initial "files to exclude" glob
    max_results     number    default 2000
    confirm_replace boolean   ask before a replace-all writes to disk

git~
    sections        string[]  default { "scm", "graph", "timeline" }, the
                              collapsible sections of the Git tab
    collapsed       string[]  sections folded on first open, default
                              { "graph", "timeline" }

buffers~
    show_unlisted   boolean   include buffers hidden from :ls
    sort            "mru"|"number"|"name"   default "mru"
    group_by_dir    boolean   group the list by directory

scm~
    groups          string[]  default { "merge", "staged", "changes",
                              "untracked" }
    collapsed       string[]  groups collapsed on first open
    confirm_discard boolean   default true, ask before any discard
    row_actions     boolean   default true, show the stage / unstage /
                              discard buttons on file rows and group
                              headers
    signoff         boolean   default false, add a Signed-off-by trailer
                              to every commit

graph~
    page_size       number    default 256, more load on scroll
    lane_colors     number    default 8, palette length before cycling
    date_format     "relative"|"short"|"iso"
    show_refs       boolean   render branch/tag badges

timeline~
    page_size       number    default 128
    follow_renames  boolean   use `git log --follow`
    follow_buffer   boolean   track the active buffer automatically

review~
    layout          "split"|"unified"
    diffopt         string[]  appended to 'diffopt' in review windows
    hunk_actions    boolean   right-aligned per-hunk buttons

buffer~
    signs            boolean  apply gitvim's sign theme to gitsigns
    blame            boolean  current-line blame virtual text
    blame_format     string   default
                     "<author>, <author_time:%R> - <summary>"
    clickable_gutter boolean  double-click a sign to expand the hunk inline;
                     composes with an existing 'statuscolumn' rather than
                     replacing it

refresh~
    debounce        number    milliseconds, default 50
    watch_gitdir    boolean   watch .git for external git operations
    events          string[]  default { "BufWritePost", "FocusGained" }

icons~
    enabled         boolean
    status          table     letters per status: modified "M", added "A",
                              deleted "D", renamed "R", copied "C", typechange "T",
                              untracked "U", ignored "I", conflict "!"

keymaps~
    enabled         boolean   default true
    prefix          string    default "<leader>g"

6. SIDEBAR TABS                                                  *gitvim-tabs*

The sidebar is an activity bar with four tabs, rendered in the window's
'winbar' and ordered by `sidebar.tabs`. Click one, cycle with <Tab> and
<S-Tab>, or jump straight to one with 1-4.

FILES                                                           *gitvim-files*
    A plain file tree rooted at the repository (or at the current directory,
    per `files.root`). <CR> opens a file in the editor window -- never inside
    the sidebar -- and toggles a directory. Expansion state is remembered per
    repository.

SEARCH                                                         *gitvim-search*
    Labelled with the magnifier icon alone. A form of four fields: Pattern,
    with VS Code's case-sensitive / whole-word / regular-expression toggles;
    Replace; Include, and Exclude for file globs. The form's state is kept per
    repository. Running the search and the replace is not implemented yet.

GIT                                                               *gitvim-git*
    The project proper: SOURCE CONTROL, GRAPH and TIMELINE as collapsible
    sections of one scrolling panel, headed by the repository name, the branch
    and the ahead/behind counters. <CR> or a double-click on a heading folds
    or unfolds a section, and the state is kept per repository.

BUFFERS                                                       *gitvim-buffers*
    The open buffers, sorted per `buffers.sort`. The current buffer is marked,
    modified ones carry a dot, and <CR> shows a buffer in the editor window.

SOURCE CONTROL                                                    *gitvim-scm*
    Collapsible groups with counts: Merge Changes, Staged, Changes and
    Untracked. Each row carries a status letter, a filetype icon and VS Code
    colouring; renames show both paths. The header shows the repository,
    branch and ahead/behind counters. Group state is remembered per repository.

    The first row is the commit line: the draft's subject (or "Message")
    and a Commit button, which reads "Commit (nothing staged)" when the
    index is clean. File rows and group headers carry right-aligned
    buttons -- `[+]` stage, `[−]` unstage, `[↩]` discard (`[+]` `[-]` `[<]`
    with ASCII icons) -- showing only the ones that apply. Click a button,
    or use the keys:

        <CR>        open the file; fold a group or section on a header
        s           stage the row (on a header: the whole group)
        u           unstage the row
        x           discard the row, after confirmation
        -           toggle between staged and unstaged
        S  U  X     stage / unstage / discard everything
        za <Space>  fold a group or section
        c           commit, see |gitvim-commit|
        C           amend HEAD
        b           check out another branch
        f  p  P     fetch / pull / push

    The sidebar refreshes itself on |BufWritePost| and |FocusGained|, and
    after git commands run outside Neovim: the git directory is watched and
    changes are debounced by `refresh.debounce`. While the sidebar is
    hidden a change only marks the status stale; it is re-read on the next
    open.

COMMIT EDITOR                                                  *gitvim-commit*
    A floating `gitcommit` buffer for a multi-line message. <C-Enter> (or
    <C-s>, for terminals that cannot send <C-Enter>) commits, `q` and <Esc>
    close it. The message is passed to `git commit -F -` on stdin, so quotes
    and shell characters arrive untouched; lines starting with `#` are
    dropped. What you type is kept as the repository's draft, so closing the
    editor loses nothing, and a successful commit clears it. An amend is
    prefilled with HEAD's message and leaves the draft alone. `--signoff`,
    or `scm.signoff`, adds a Signed-off-by trailer.

GRAPH                                                           *gitvim-graph*
    (planned) `git log` rendered with per-branch coloured lanes. Selecting a
    commit lists its changed files; selecting a file opens |gitvim-review| for
    that commit against its parent.

TIMELINE                                                     *gitvim-timeline*
    (planned) History of one file via `git log --follow`, rendered through the
    same lane engine as the graph.

7. REVIEW VIEW                                                 *gitvim-review*

(planned) A two-pane diff using Neovim's native diff mode, so filler lines,
scrollbind, folding of unchanged regions and word-level highlighting all come
from the editor itself. Each hunk carries right-aligned `[+]` `[<]` `[^]`
buttons for stage, revert and expand.

==============================================================================
8. BUFFER LAYER                                                *gitvim-buffer*

gitvim themes gitsigns' signs with the same semantic colours as the sidebar,
shows current-line blame as virtual text, and installs an optional clickable
gutter. Double-clicking a sign expands that hunk inline; right-clicking opens
a hunk action menu. An existing 'statuscolumn', including a dynamic one such
as snacks.statuscolumn, is composed rather than replaced.

Default mappings (under `keymaps.prefix`, `<leader>g` by default):

    hs    stage hunk                 hu    undo last staged hunk
    hr    reset hunk                 hp    preview hunk inline
    hb    show line blame            tb    toggle current-line blame
    hB    select blamed commit in GRAPH

    s     stage the file             u     unstage the file
    x     discard the file           S     stage all changes
    c     commit                     C     amend HEAD
    f     fetch                      p     pull
    P     push

A mapping is only made where the key is free: gitvim never replaces or
shadows an existing mapping, global or buffer-local. If a global mapping on
the same key is defined later (LazyVim's `<leader>gs`, `<leader>gc`, ... on
VeryLazy), gitvim's map is removed and yours wins. The public Lua helpers
`require("gitvim").toggle_blame()` and
`require("gitvim").open_blame_commit()` provide the same blame actions.

9. HIGHLIGHTS                                              *gitvim-highlights*

All groups are linked to existing semantic groups, never hardcoded colours, so
they follow your colorscheme.

    GitVimAdded             new file / added hunk
    GitVimModified          modified file / changed hunk
    GitVimDeleted           deleted file / removed hunk
    GitVimUntracked         untracked file
    GitVimRenamed           renamed file
    GitVimConflict          unmerged file
    GitVimBlame             current-line blame text
    GitVimGraphLane1..8     graph lane palette

Override with |:highlight| after your colorscheme loads.

==============================================================================
10. HEALTH                                                     *gitvim-health*

>vim
    :checkhealth gitvim
<
Reports the Neovim and git versions, whether gitsigns, snacks and mini.icons
were found, whether 'mouse' is enabled for click handling, and whether the
current directory is inside a git repository.

11. DEVELOPMENT                                           *gitvim-development*

>bash
    make test        # headless plenary suite
    make test-file FILE=tests/gitvim/fixture_spec.lua
    make fmt         # stylua
    make lint        # luacheck
    make docs        # regenerate doc/tags
    make all         # fmt-check + lint + test
<
Dependencies are cloned into `.tests/` on the first run. Tests build a
deterministic throwaway repository (branch, merge, rename, and a dirty
worktree covering every status group) via `tests/fixture.lua`.
