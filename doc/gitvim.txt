1. INTRODUCTION                                          *gitvim-introduction*

gitvim.nvim assembles Neovim's Git capabilities into one docked, discoverable
surface modelled on VS Code's Source Control view, plus GitLens-style blame
and a Git Graph-style commit graph.

It is an orchestration layer. gitvim owns the sidebar, the graph, the
timeline, the commit UI and the remote operations; it delegates the
in-buffer layer (signs, hunks, blame) to gitsigns.nvim through a single
bridge module, so the coupling stays thin and auditable.

==============================================================================
2. REQUIREMENTS                                          *gitvim-requirements*

    Neovim 0.11 or newer
    git 2.30 or newer
    gitsigns.nvim                   (required) signs, blame, hunk staging
    ripgrep                         (optional) the Search tab; falls back to
                                    `git grep`, which searches tracked files
                                    only and cannot expand `$1`
    mini.icons or nvim-web-devicons (optional) filetype icons
    snacks.nvim                     (optional) nicer pickers, inputs and
                                    notifications: gitvim only calls
                                    |vim.ui.select()|, |vim.ui.input()| and
                                    |vim.notify()|, whoever provides them
    a Nerd Font                     (optional) see `icons.style`

Every optional dependency has a fallback. Run |:checkhealth| gitvim to see
what was detected.

3. SETUP                                                        *gitvim-setup*

With lazy.nvim: >lua

    {
      "mihovilrak/gitvim.nvim",
      dependencies = { "lewis6991/gitsigns.nvim" },
      cmd = "GitVim",
      keys = {
        { "<leader>gg", "<cmd>GitVim toggle<cr>", desc = "GitVim sidebar" },
      },
      opts = {},
    }
<
                                                              *gitvim-lazyvim*
In LazyVim, drop the same spec into `lua/plugins/gitvim.lua`. gitsigns and
snacks are already there, and LazyVim's own `<leader>g` maps take precedence
over gitvim's buffer maps (see |gitvim-keymaps|); pick another prefix to get
all of them: >lua

    return {
      "mihovilrak/gitvim.nvim",
      dependencies = { "lewis6991/gitsigns.nvim" },
      cmd = "GitVim",
      keys = {
        { "<leader>gv", "<cmd>GitVim toggle<cr>", desc = "GitVim sidebar" },
      },
      opts = {
        keymaps = { prefix = "<leader>v" },
      },
    }
<
Calling `setup()` is optional if you are happy with the defaults; the
|:GitVim| command initialises the plugin on first use.

                                                            *gitvim.setup()*
require("gitvim").setup({opts})
    Merge {opts} over the defaults and initialise. Safe to call once; repeat
    calls are ignored.

                                                             *gitvim.open()*
require("gitvim").open({tab})
    Open the sidebar, optionally focusing {tab} ("files", "search", "git"
    or "buffers").

                                                            *gitvim.close()*
require("gitvim").close()

                                                           *gitvim.toggle()*
require("gitvim").toggle({tab})
    Open the sidebar if it is closed, close it otherwise.

                                                          *gitvim.refresh()*
require("gitvim").refresh({path}, {cb})
    Re-read git status for the repository around {path} (default: the
    current buffer). {cb} is called as `cb(err, store)`.

                                                           *gitvim.review()*
require("gitvim").review({root}, {path}, {opts})
    Open |gitvim-review| for {path}, relative to {root}. See the example
    there for {opts}.

                                                     *gitvim.toggle_blame()*
require("gitvim").toggle_blame({value})
    Toggle current-line blame, or set it to {value}. Returns the new state.

                                                *gitvim.open_blame_commit()*
require("gitvim").open_blame_commit()
    Select the current line's commit in |gitvim-graph|.

                                                           *gitvim.config()*
require("gitvim").config()
    The merged configuration table. Read it; do not modify it.

4. COMMANDS                                                  *gitvim-commands*

                                                                    *:GitVim*
                                                                *:GitVim-open*
:GitVim open [{tab}]    Open the sidebar. {tab} is "files", "search",
                        "git" or "buffers"; defaults to
                        `sidebar.default_tab`.
                                                               *:GitVim-close*
:GitVim close           Close the sidebar.
                                                              *:GitVim-toggle*
:GitVim toggle          Toggle the sidebar.
                                                               *:GitVim-blame*
:GitVim blame           Toggle current-line blame.
                                                        *:GitVim-blame-commit*
:GitVim blame-commit    Select the current line's commit in GRAPH.
                                                               *:GitVim-stage*
:GitVim stage           Stage the current file.
                                                             *:GitVim-unstage*
:GitVim unstage         Unstage the current file.
                                                             *:GitVim-discard*
:GitVim discard         Discard the current file's working-tree changes
                        (an untracked file is deleted).
                                                           *:GitVim-stage-all*
:GitVim stage-all       Stage every change, untracked files included.
                                                         *:GitVim-unstage-all*
:GitVim unstage-all     Unstage everything.
                                                         *:GitVim-discard-all*
:GitVim discard-all     Discard every working-tree change and delete
                        untracked files. Staged changes are kept.
                                                              *:GitVim-commit*
:GitVim commit [--amend] [--signoff]
                        Open the commit message editor, see
                        |gitvim-commit|.
                                                               *:GitVim-fetch*
:GitVim fetch           Fetch from the remotes.
                                                                *:GitVim-pull*
:GitVim pull            Pull the current branch.
                                                                *:GitVim-push*
:GitVim push            Push the current branch. A branch without an
                        upstream is published with `--set-upstream`.
                                                            *:GitVim-checkout*
:GitVim checkout        Pick another local branch and switch to it.
                                                              *:GitVim-review*
:GitVim review [{rev}]  Open |gitvim-review| for the current file: the
                        index against the working tree, or {rev} against
                        the working tree.
                                                            *:GitVim-timeline*
:GitVim timeline [{path}]
                        Show a file's history in |gitvim-timeline|:
                        {path} is pinned there; without it, the current
                        file is shown (unless another file is pinned).
                                                             *:GitVim-refresh*
:GitVim refresh         Re-read git status for the current repository.
                                                              *:GitVim-status*
:GitVim status          Echo a one-line summary of the repository.
                                                              *:GitVim-health*
:GitVim health          Run |:checkhealth| gitvim.

Subcommands and the commit flags complete with <Tab>. Every discard asks
for confirmation first unless `scm.confirm_discard` is false. Remote
operations report their progress with |vim.notify()|.

6. SIDEBAR TABS                                                  *gitvim-tabs*

The sidebar is an activity bar with four tabs, rendered in the window's
'winbar' and ordered by `sidebar.tabs`. Click one, cycle with <Tab> and
<S-Tab>, or jump straight to one with 1-4.

                                                         *gitvim-sidebar-keys*
Keys that work on every tab:

    <Tab>  <S-Tab>  next / previous tab
    1  2  3  4      jump to a tab, in `sidebar.tabs` order
    <CR>            the row's action (each tab lists its own)
    <2-LeftMouse>   the same, with the mouse; single clicks hit buttons
    R               refresh
    q               close the sidebar

FILES                                                           *gitvim-files*
    A plain file tree rooted at the repository (or at the current directory,
    per `files.root`). <CR> opens a file in the editor window -- never inside
    the sidebar -- and toggles a directory. Expansion state is remembered per
    repository.

SEARCH                                                         *gitvim-search*
    Labelled with the magnifier icon alone. A form of four fields: Pattern,
    with VS Code's case-sensitive / whole-word / regular-expression toggles;
    Replace; Include, and Exclude for file globs. The form's state is kept per
    repository.

    The search runs as the form changes, asynchronously, through ripgrep
    when `rg` is executable and `git grep` otherwise, and stops after
    `search.max_results` matches (the summary then says "capped"). Include
    and Exclude take comma-separated globs with ripgrep's semantics: `*.lua`
    matches at any depth, `docs/**` everything under docs. Results are
    grouped per file under a foldable header with a count.

    With a Replace text every match previews its replacement inline. In regex
    mode ripgrep expands capture groups: `$1`, `${name}`, and `${0}` for the
    whole match (write `${1}x`, not `$1x`). Other modes replace literally.

    Keys~
        <CR>, i     edit the field under the cursor
        <M-c>       toggle case-sensitive
        <M-w>       toggle whole word
        <M-r>       toggle regular expression
        <C-l>       clear the search and its results
        R           run the search again
        <CR>        on a file header: fold it; on a match: open the file at
                    the match in the editor window, never in the sidebar
        r           replace the match's line, or a file header's file
        A           replace every result; `[replace all]` does the same

    Replacing a file or all results asks first when `search.confirm_replace`
    is set; a single line never asks. Each file is changed in one undo block
    and written, except a buffer that already had unsaved edits, which is
    left unsaved. A line that changed since the search is skipped, and the
    search re-runs afterwards.

GIT                                                               *gitvim-git*
    The project proper: SOURCE CONTROL, GRAPH and TIMELINE as collapsible
    sections of one scrolling panel, headed by the repository name, the branch
    and the ahead/behind counters. <CR> or a double-click on a heading folds
    or unfolds a section, and the state is kept per repository.

BUFFERS                                                       *gitvim-buffers*
    The open buffers, sorted per `buffers.sort`. The current buffer is marked,
    modified ones carry a dot, and <CR> shows a buffer in the editor window.

SOURCE CONTROL                                                    *gitvim-scm*
    Collapsible groups with counts: Merge Changes, Staged, Changes and
    Untracked. Each row carries a status letter, a filetype icon and VS Code
    colouring; renames show both paths. The header shows the repository,
    branch and ahead/behind counters. Group state is remembered per
    repository.

    The first row is the commit line: the draft's subject (or "Message")
    and a Commit button, which reads "Commit (nothing staged)" when the
    index is clean. File rows and group headers carry right-aligned
    buttons -- `[+]` stage, `[−]` unstage, `[↩]` discard (`[+]` `[-]` `[<]`
    with ASCII icons) -- showing only the ones that apply. Click a button,
    or use the keys:

        <CR>        open |gitvim-review|; fold a group or section on a header
        o           open the file itself
        s           stage the row (on a header: the whole group)
        u           unstage the row
        x           discard the row, after confirmation
        -           toggle between staged and unstaged
        S  U  X     stage / unstage / discard everything
        za <Space>  fold a group or section
        c           commit, see |gitvim-commit|
        C           amend HEAD
        b           check out another branch
        f  p  P     fetch / pull / push

    The sidebar refreshes itself on |BufWritePost| and |FocusGained|, and
    after git commands run outside Neovim: the git directory is watched and
    changes are debounced by `refresh.debounce`. While the sidebar is
    hidden a change only marks the status stale; it is re-read on the next
    open.

COMMIT EDITOR                                                  *gitvim-commit*
    A floating `gitcommit` buffer for a multi-line message. <C-Enter> (or
    <C-s>, for terminals that cannot send <C-Enter>) commits, `q` and <Esc>
    close it. The message is passed to `git commit -F -` on stdin, so quotes
    and shell characters arrive untouched; lines starting with `#` are
    dropped. What you type is kept as the repository's draft, so closing the
    editor loses nothing, and a successful commit clears it. An amend is
    prefilled with HEAD's message and leaves the draft alone. `--signoff`,
    or `scm.signoff`, adds a Signed-off-by trailer.

GRAPH                                                           *gitvim-graph*
    The history of every branch, remote and tag, newest first, drawn with
    per-branch coloured lanes. Each commit row shows its `●` node (HEAD's in
    its own colour), ref badges -- the current branch, other local branches,
    remotes and tags each in their own colour, hidden with
    `graph.show_refs = false` -- then the subject, with the author and the
    date (`graph.date_format`) at the right edge.

    History arrives `graph.page_size` commits at a time: scrolling the
    "Load more…" row into view fetches the next page, and the lanes carry on
    across it. The graph reloads itself when HEAD, the branch or its
    upstream moves.

        <CR>        on a commit: list its changed files, or fold them again;
                    on a file: open |gitvim-review| for that commit against
                    its first parent (a root commit against the empty tree)
        za <Space>  fold or unfold a commit's files
        o           open a listed file as it is in the worktree
        R           reload the history

    `:GitVim blame-commit` (or `hB` in a buffer) selects a line's commit
    here, loading further pages until it is found.

TIMELINE                                                     *gitvim-timeline*
    The history of one file, newest first, drawn through the same lane
    engine and row layout as GRAPH: node, ref badges, subject, author and
    date. With `timeline.follow_renames` (the default) it runs through
    `git log --follow`, so the history carries on past a rename; the commit
    that renamed or copied the file gets an extra "renamed from {old}" row.

    The section follows the file in the active editor window. Scratch and
    special buffers, and files outside the repository, leave the last file
    in place. Pin a file to keep it while you move around; with
    `timeline.follow_buffer = false` the first file shown is pinned for you.
    History arrives `timeline.page_size` revisions at a time, and scrolling
    the "Load more…" row into view fetches the next page. The pages come
    from one `git log`, paused between pages, so deep history is read only
    once; after 30 seconds idle it is ended, and started again when the next
    page is asked for. The timeline reloads itself on every refresh and
    whenever HEAD, the branch or its upstream moves.

    An untracked file says so without asking git, a staged file that has
    never been committed shows "Not committed yet.", and a file git has
    never seen shows "No history.".

        <CR>        on a revision: open |gitvim-review| for it against its
                    first parent (a root commit against the empty tree),
                    under the file's name at the time
        gw          on a revision: review it against the working tree
        t           pin the file shown, or unpin and follow the buffer again
                    (<CR> on the header row does the same)

    `:GitVim timeline [{path}]` pins {path}, or shows the current file
    when no path is given, and opens the Git tab on it.

7. REVIEW VIEW                                                 *gitvim-review*

A two-pane diff using Neovim's native diff mode, so filler lines, scrollbind,
folding of unchanged regions and word-level highlighting all come from the
editor itself. The right pane takes over the editor window; the left pane is
split off beside it. `review.diffopt` is merged into 'diffopt' while the view
is open and the old value is restored when it closes.

<CR> on a SOURCE CONTROL row opens it: a Changes or Untracked row shows the
index against the working tree, a Staged row shows HEAD against the index.
Conflicted files and submodules open as plain files. |:GitVim| review opens
the current buffer's file. From Lua: >lua

    require("gitvim").review(root, path, {
      left_rev = "HEAD~1",   -- default ":" (the index)
      right_rev = "HEAD",    -- default: the working tree; ":" for the index
      left_path = "old.lua", -- the left side's path, for a rename
    })
<
Each hunk carries right-aligned buttons, shown only where they apply:

    `[+]`   stage the hunk          index | working tree
    `[−]`   unstage the hunk        HEAD | index
    `[↩]`   revert the hunk         any rev | working tree, after confirmation
    `[⤢]`   expand: unfold all the context, and fold it back

With ASCII icons they read `[+]` `[-]` `[<]` `[^]`. `review.hunk_actions =
false` hides them; the keys still work. The buttons are never virtual lines,
which would push one pane out of line with the other. Keys, in either pane:

    ]h  [h      next / previous hunk
    s           stage the hunk under the cursor
    u           unstage it
    x           revert it (a buffer with unsaved changes is left alone)
    o           expand / collapse the context
    R           reload both panes
    q           close the review

`keymaps.prefix` .. `hs` / `hu` / `hr` work too when `keymaps.enabled` is set.
Staging writes the new index blob directly (`git hash-object` and `git
update-index`), so a hunk is staged exactly as shown, line endings included.
Deleted, untracked and renamed files work like any other; binary files,
symlinks and submodules are shown as a placeholder without hunks.

`layout = "unified"` is not implemented yet and falls back to "split".

8. BUFFER LAYER                                                *gitvim-buffer*

gitvim themes gitsigns' signs with the same semantic colours as the sidebar,
shows current-line blame as virtual text, and installs an optional clickable
gutter. Double-clicking a sign expands that hunk inline; right-clicking opens
a hunk action menu. An existing 'statuscolumn', including a dynamic one such
as snacks.statuscolumn, is composed rather than replaced.

                                                              *gitvim-keymaps*
Default mappings (under `keymaps.prefix`, `<leader>g` by default):

    hs    stage hunk                 hu    undo last staged hunk
    hr    reset hunk                 hp    preview hunk inline
    hb    show line blame            tb    toggle current-line blame
    hB    select blamed commit in GRAPH

    s     stage the file             u     unstage the file
    x     discard the file           S     stage all changes
    c     commit                     C     amend HEAD
    f     fetch                      p     pull
    P     push

A mapping is only made where the key is free: gitvim never replaces or
shadows an existing mapping, global or buffer-local. If a global mapping on
the same key is defined later (LazyVim's `<leader>gs`, `<leader>gc`, ... on
VeryLazy), gitvim's map is removed and yours wins. The public Lua helpers
`require("gitvim").toggle_blame()` and
`require("gitvim").open_blame_commit()` provide the same blame actions.

    GitVimGraphLane7        Special           lane colour 7
    GitVimGraphLane8        Number            lane colour 8

    Review and buffer layer~
    GitVimHunkButton        Special           per-hunk buttons in review
    GitVimReviewLabel       Title             pane labels in review
    GitVimBlame             Comment           current-line blame text

When `buffer.signs` is set, gitsigns' own groups are linked to these, so
signs share the sidebar's colours: `GitSigns{Add,Change,Changedelete,Delete,`
`Topdelete,Untracked}`, each with its `Nr` and `Cul` variants and the
`GitSignsStaged*` counterparts, and `GitSignsCurrentLineBlame` (to
GitVimBlame). These links are set on every |ColorScheme|, so override the
GitVim group rather than the GitSigns one.

Override with |:highlight| after your colorscheme loads.

10. HEALTH                                                     *gitvim-health*

>vim
    :checkhealth gitvim
<
Checks, in four sections:

editor~
    Neovim 0.11+, and whether 'mouse' is set (clicks need it; every action
    also has a key).
dependencies~
    gitsigns.nvim, and that it exposes every function gitvim calls (an
    outdated gitsigns is an error); snacks.nvim; the icon provider; ripgrep,
    or a warning about the `git grep` fallback; git 2.30+.
configuration~
    Whether `setup()` has run; `icons.style` against `vim.g.have_nerd_font`;
    `buffer.clickable_gutter` with 'mouse' off, or composed with your own
    'statuscolumn'; buffer keymaps that yield to an existing global mapping
    (see |gitvim-keymaps|), and a mapping on the prefix itself, which makes
    every key under it wait for 'timeoutlen'.
repository~
    The work tree, git directory, HEAD and upstream around the current
    buffer (or the working directory), and whether `user.name` and
    `user.email` are set -- without them every commit fails.

11. PERFORMANCE                                           *gitvim-performance*

git runs off the main loop, always: every call goes through |vim.system()|
with a callback, and parsing large output yields between chunks. The
release gates, measured by `scripts/bench.lua` on a generated repository
with 10k+ commits and 1k+ changed files (`make bench`):

    sidebar open, first paint                  < 200 ms
    GRAPH first page rendered                  < 150 ms
    longest main-loop block during a refresh   < 16 ms

The measured numbers are recorded in Plan.md.

12. DEVELOPMENT                                           *gitvim-development*

>bash
    make test        # headless plenary suite
    make test-file FILE=tests/gitvim/fixture_spec.lua
    make fmt         # stylua
    make lint        # luacheck
    make docs        # regenerate doc/tags
    make bench       # performance gates, see |gitvim-performance|
    make all         # fmt-check + lint + test
<
Dependencies are cloned into `.tests/` on the first run. Tests build a
deterministic throwaway repository (branch, merge, rename, and a dirty
worktree covering every status group) via `tests/fixture.lua`.
